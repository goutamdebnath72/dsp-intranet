Snapshot before omnibar accuracy overhaul

State of the app as tested on 8-9 Oct 2026. No code changes in this commit;
it exists so the overhaul can be reviewed and rolled back step by step.

Included:
- Omnibar employee/department answers via model-written SQL over the nlq views
  (guarded, paged, with thumbs feedback, verified-answer cache and examples)
- Structured holiday engine (counts, lists, ranges, months, comparisons, RH quota)
- Circular search and Executive Deep Synthesis with the pre-LLM year/population filter
- Two-pass OCR ingestion (eng + hin+eng+ben) and headline-only embeddings for
  holiday-list circulars

Baseline: tsc --noEmit reports 0 errors on this tree.

Known issues recorded in the test ledger (66 items), to be fixed in follow-up commits:
- Department code and name not always returned together; "most/top" answers
  not tie-safe; name matching differs between phrasings
- "categories" is mistaken for a category name in holiday questions; two-row
  "when is" answers omit categories and note
- Second OCR pass corrupts Latin digits (e.g. 15,000 stored as 75,000), and
  both copies are stored
- Synthesis sees one chunk per circular and can miss the answering text
- Plain search can rank a wrong-year circular above a right-year one
