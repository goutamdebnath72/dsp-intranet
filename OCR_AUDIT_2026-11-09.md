# OCR audit of the archive (9 Nov 2026) - corrected

**Correction.** The first version of this file listed "defects" (31.12.2005, wrong phone digits, wrong Hindi table amounts). Those were in the pipeline's FRESH re-read
(the cache of `scripts/reread-circulars.ts`), which `scripts/check-readings.ts` compares. They are NOT in the text stored in the database, which was corrected earlier
by the re-read/merge work (105 backups in `reread-backups/`). The tool below compares the STORED text itself.

## Method
`scripts/ocr-consensus.ts` (logic in `src/lib/ingestion/consensusPatch.ts`, 19 selftests). For every stored page (159 pages, 55 circulars; 31 pages skipped: roster pages stored
as rows, or a page with no stored text) the stored text is compared word by word with two other independent readings of the same page IMAGE (Gemini 3.1 Pro and Gemini 3.8 Flash).
A conflict between the readers goes to an exact arbiter, the PDF's own text layer, when the PDF has one. Rules: a number is replaced only when both readers propose the same
replacement (or the PDF layer contains the one version and not the other); a word is never changed; a difference that is only spacing, dash type or a superscript ordinal is cosmetic.

## Result (stored text, dry run and applied)
- Numbers (tokens with a digit): 3,902. Confirmed by at least one independent reader: 3,876 (99.3%). Words: 44,925 of 45,268 confirmed (99.2%).
- Patches needed: **0**. Wherever both readers agree, the stored text already matches them.
- Conflicts where only ONE reader disagrees with the stored text: 8 were settled in favour of the stored text by the PDF text layer (so the reader was wrong, e.g. "2024" for 2026
  on circulars 43 and 53). 41 remain unsettled; almost all are labels ("Column 3" against a Hindi header) or handwritten dates beside signatures.
- Checked by eye (page crops): circular 40's printed date 15/12/2025 is correct as stored. Circular 18's handwritten signature date reads 13/12/23 but the stored text has 31/12/23
  (a real misread of a signature date; not used in any answer; not corrected because it is outside the two-reader rule).
- 159 page checks were saved in `circular_page_check` (the answer card refuses a number that no reader confirmed). Nothing in the stored text was changed.

## Earlier checks (still valid)
- 15 PDFs with an embedded text layer compared with the stored text: 10 identical, 5 not comparable (their text layer is junk from old Hindi fonts).
- Full two-reader page check of the pipeline's fresh reading (Flash and Pro, 168 pages): 112 pages agree on every number. Its differences are about the fresh re-read, not the database.

## Limits
- The readers are Gemini models and tesseract, not a human; agreement is strong evidence, not proof. Handwriting, stamps and illegible spots can be misread by all of them.
- Words are reported, never patched (a model may correct a typo that is really in the original).
- Pages whose stored text is a roster (health check-up lists) are verified by a different mechanism (HR directory match), not by this tool.
